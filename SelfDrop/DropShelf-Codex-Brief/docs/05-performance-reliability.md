# Performance and reliability contract

## Budget
Owner requirement: maximum 100 MB RAM. Use 100,000,000 bytes as conservative acceptance threshold for app process physical footprint; report exact metric/tool and peak sampling interval. This is a product acceptance test, not a guaranteed OS-enforced limit. Include helpers if any are introduced; none planned. Target idle 20–50 MB (aspirational), near-zero idle CPU (proposed measurable target <1% average of one core over 5 min, quiet machine, record environment). App must not noticeably impair MacBook responsiveness. Measure optimized Release build outside debugger, then use Instruments separately to diagnose overhead. Measure baseline macOS version, chip/RAM, display count and build configuration.

## Strategy
- Existing files never read into memory merely to stage or drag; no recursive scan, copying, hashing or full-size previews. File URL payloads only. Metadata work bounded; offline/cloud volumes must not be forced to download on intake.
- Pure AppKit where beneficial, no third-party packages/browser/server. Create expensive shelf UI lazily. Visible thumbnails only, use ImageIO thumbnail max pixel size (proposed 160–256 px, include Retina scale) or native icons/Quick Look as measured. Avoid decoding full-size images first. Native decoder transient allocations still need measurement. Placeholder for huge or unsupported assets.
- Proposed starting preview cache hard application-owned cost budget 8 MiB decoded pixels (actual bytesPerRow × height), max 32 entries, LRU eviction; use explicit accounting, not only advisory NSCache limits. Avoid duplicate copies in views. Max 1–2 concurrent thumbnail jobs; bounded queue (e.g. 32), cancel offscreen work. Tune down based on measurements. Release caches on memory pressure and collapse. No full-res image clipboard operation unless measured safe/approved.
- Proposed manual reference cap 500 per session with clear non-destructive refusal of additional entries (owner did not specify a cap). Tune after measurement; never silently evict manual entries. Use lazy scrolling and bound bookmarks/metadata size.
- Event-driven monitoring and one-shot expiry scheduling; no persistent polling, no idle animation, no continuous timer. Coalesce notification bursts. No synchronous network/remote-volume access on main actor. Use task cancellation, weak captures and explicit teardown. Avoid blocking UI while errors or permission dialogs occur.
- Memory pressure handling: cancel unnecessary work, clear caches, downgrade to icons, stop accepting optional heavy jobs; no claim that this guarantees total process footprint. If budget breached in tests, optimize or disable optional features and rerun; do not ship unverified or change requirements without owner.

## Reliability
No force unwraps for user-controlled inputs, no fatal errors on recoverable failure, no broad catch-and-ignore. Track pending/accepted/rejected separately. Preserve valid entries on rejected drag. Handle permission denial, moved/deleted files, mount changes, sleep/wake, display removal, full-screen switching, rapid intake, duplicate events, drag cancellation, and UI teardown. Crash/restart starts empty by requirement; do not add recovery persistence. OSLog categories with private file paths; avoid logging file contents or screenshot names by default. No network/analytics. Never auto-delete originals.
