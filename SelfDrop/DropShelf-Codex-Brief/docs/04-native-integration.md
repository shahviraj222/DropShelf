# macOS integration

## Window feasibility first
Use NSPanel / NSWindow, appropriate floating level and nonactivating panel where workable. Consider LSUIElement or accessory activation policy for no Dock icon (proposed). Test keyboard access without stealing normal app focus. Use public NSWindow.CollectionBehavior options supported by installed SDK: evaluate canJoinAllSpaces/fullScreenAuxiliary and newer canJoinAllApplications with availability checks; avoid incompatible combinations and blindly combining flags. Full-screen apps, Stage Manager and Spaces are not equivalent to maximized windows. Verify on target OS; no promise to overlay secure/system screens. Use NSScreen frame/visibleFrame, screen-parameter notifications and workspace events. Proposed initial single panel anchored to active/selected screen, not a panel per monitor; multi-display choice open. On display disconnect reposition to surviving screen. No global mouse polling.

## Real file transfer
Register destination view for file URL pasteboard types; use NSPasteboard readObjects(forClasses:options:) with NSURL and file-only reading options. Check isFileURL. Preserve directory identity and filenames. Support multiple URLs. Incoming offer copy operation (reference registration only) so source is not asked to delete original. Never advertise move/delete as a side effect of intake.

Outgoing: create one NSDraggingItem(pasteboardWriter: url as NSURL) per selected file; set a small native dragging image/frame; initiate NSView.beginDraggingSession(with:event:source:) from actual pointer event and implement NSDraggingSource. Use operation mask copy as conservative default; do not implement file copy itself. Observe terminal callback and release resources. Never call setString(path, forType: .string) as file transfer. Receiving application chooses whether to attach, open or copy depending on drop zone and offered operations. Verify actual bytes at destination vs Finder baseline. Native file URL is a reference to a file, not a web link or textual path. No guarantee of acceptance by arbitrary apps.

## File references / access
Use URL resource values and optional bookmark data in memory. Ordinary bookmarks can sometimes resolve moved/renamed files, not guaranteed. If sandboxing chosen, use appropriate user-selected read-only access, security-scoped bookmarks when needed/supported, balance start/stopAccessingSecurityScopedResource. Verify cross-app access on actual build/signing configuration. No persisted bookmarks. Avoid full disk access and permission bypass. Local development sandbox/distribution choice unresolved; record entitlements, user-visible permission rationale, and test denied/revoked access. External volume unmount marks unavailable; revalidate after mount or user retry. Never delete/move originals.

## Automatic screenshots
Use FSEvents file-events mode (or justified public event-driven alternative). User-select screenshot folder; default Desktop suggestion, not guaranteed screenshot location; no reliance on undocumented settings as sole mechanism. Baseline existing entries without importing old screenshots. Subscribe before/with baseline and reconcile startup race; filter new files only. FSEvents coalesces events, may signal parent directories or missed events; bounded directory reconciliation on required flags, no recursive full-disk scan, no periodic polling. For candidate files, verify file readiness and screenshot metadata if present (kMDItemIsScreenCapture / relevant xattr may be OS-dependent and delayed). Prefer reliable metadata, bounded delayed retry when file still being written; if metadata unavailable, use conservative configured filename heuristic only if explicitly documented and tested, avoid collecting unrelated downloads. No claim of perfect classifier. Dedup burst notifications. Apply 10-item cap and 1-hour expiry. Denied folder access disables auto feature gracefully while manual drag still works. Restart starts empty; wake reconciles only eligible new files since current session, no stale history.

Native floating screenshot preview: actual drag may be file URL, file promise, or image data; inspect pasteboard types locally with redacted logs. Accept durable readable file URL without copying. File promises (NSFilePromiseReceiver) or clipboard-only pixels need materialization or owned memory; defer unapproved storage exception. If preview can only be received via promise, explain unsupported in reference-only mode and suggest waiting for normal screenshot save; never silently consume original preview or report success. No screenshot interception or screen-recording permission. Clipboard manual paste supports file URLs first; raw image-only and Quick Copy image data are optional subject to budget/approval. No background clipboard polling, auto paste or accessibility permissions.
